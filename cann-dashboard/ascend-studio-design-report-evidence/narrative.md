# Ascend Studio 设计汇报叙事

受众：产品与设计评审。需要讨论设计点能否被理解、体验是否连贯，以及知识供给如何支撑它们。

核心判断：以一次任务或一次学习为起点，让表达、理解、实践、收获与下一次使用连接起来。专业程度是引导深度的维度，不直接等同于任务用户或学习用户。

用户已选 A「一条旅程、两种起点」。学习导向同时容纳目标模糊与目标明确者，不额外拆成互斥人群。

| 章节 | 回答的问题 | 设计响应 | 素材与边界 |
|---|---|---|---|
| 用户旅程 | 两类用户在哪里遇到断点 | 五阶段共同旅程，分别呈现行为 | 旧精简报告 #5 + 本轮讨论；感受和痛点为设计推演 |
| 表达目标 | 为什么空白 Prompt 有门槛 | 主动建议、线索串联、可编辑 Prompt | 现有线上原型；历史记录为示例 |
| 边做边懂 | 任务完成为什么未必学会 | 操作与图解联动、社区草稿 | 现有线上原型；不发送真实社区内容 |
| 自主学习 | 学什么、怎样学才适合自己 | 意图路径、共创调整、个人认知 | 路径与实践为截图；个人认知为目标体验示意 |
| 移动续学 | 离开电脑怎样继续 | 微信通知、速览、短知识卡、任务小结 | 本地小程序原型；真实推送受平台能力和授权约束 |
| 知识供给 | 提供方需要交付什么 | 四个问题的知识单元 + 多入口及经验回流 | 新绘目标服务图；不宣称后台已实现 |

验证关注：能否形成目标、理解并调整路径、说明修改原因、迁移到相似问题、再次使用个人或社区经验、跨场景继续任务。没有虚构效果数字。

组件路由：封面沿用 deck-template；旅程复用内置 user-journey；截图设计页复用黑底 §8；知识例证与服务图按图文 §14；原生翻页、概览、导航点、全屏和键盘运行时整套保留并补齐 hash 恢复。
