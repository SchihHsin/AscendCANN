# Ascend Studio 设计汇报叙事

受众：产品与设计评审。需要讨论设计点能否被理解、体验是否连贯，以及知识供给如何支撑它们。

核心判断：以一次任务或一次学习为起点，让表达、理解、实践、收获与下一次使用连接起来。专业程度是引导深度的维度，不直接等同于任务用户或学习用户。

用户已选 A「一条旅程、两种起点」。学习导向同时容纳目标模糊与目标明确者，不额外拆成互斥人群；两类起点都可以覆盖不同经验程度。

| 章节 | 回答的问题 | 设计响应 | 素材与边界 |
|---|---|---|---|
| 开发入口对照 | 同一开发目标下，资料检索与 Agent 委托的起点有何不同 | 并排呈现 IDE 与官网 / 社区的多窗口检索，以及集成式 Agent 任务工作区 | 透视构图由 ImageGen 提供；昇腾侧将本轮核对的 1440×900 开发者主页截图贴入主窗口，搭配 IDE 场景；Codex 侧将仓库原有任务简报 `12-codex-task-brief.png` 中的任务简报与 Context 面板贴入工作区主体，外侧会话导航参考截图布局。两者表示工作方式，不表示两类固定人群或实时产品状态 |
| 用户旅程 | Ascend Studio 之前，任务与学习各自如何推进、在哪里失去把握 | 按参考矩阵呈现：五阶段为列，触点、Thinking、Doing、Feeling、设计痛点和机会点为行；Doing 行用时序图呈现两类开发者、Agent、环境与知识渠道的交接。两类用户按当前目标区分，不按专业程度区分；模糊兴趣与明确目标都属于学习旅程 | 旧精简报告 #5 的可编辑 HTML / CSS + 用户给的旅程结构参考；每行五列严格对齐；两条把握感曲线是定性体验推演，不是访谈测量；每阶段保留多条具体痛点 |
| 表达目标 | 为什么空白 Prompt 有门槛 | 主动建议、线索串联、可编辑 Prompt | 现有线上原型；历史记录为示例 |
| 边做边懂 | 任务完成为什么未必学会 | 操作与图解联动、社区草稿 | 现有线上原型；不发送真实社区内容 |
| 自主学习 | 学什么、怎样学才适合自己 | 意图路径、共创调整、个人认知 | 路径与实践为截图；个人认知为目标体验示意 |
| 移动续学 | 离开电脑怎样继续 | 微信通知、速览、短知识卡、任务小结 | 本地小程序原型；真实推送受平台能力和授权约束 |
| 知识供给 | 提供方需要交付什么 | 四个问题的知识单元 + 多入口及经验回流 | 新绘目标服务图；不宣称后台已实现 |

验证关注：能否形成目标、理解并调整路径、说明修改原因、迁移到相似问题、再次使用个人或社区经验、跨场景继续任务。没有虚构效果数字。

组件路由：封面沿用 deck-template；开发入口页用两张基于现有产品截图的透视情景图，左侧呈现昇腾社区官网与独立 IDE 窗口，右侧呈现 Codex 任务简报、会话列表与 Context 面板。ImageGen 仅负责透视场景、IDE 外观与 Codex 外侧导航；官网页面与 Codex 中部任务简报 / Context 面板使用现有截图并透视映射，避免重新生成这些产品界面细节。用户旅程复制精简报告 #5 的可编辑网格作为底稿，不嵌入整页截图，内容明确为 Ascend Studio 之前的开发方式。旅程行按参考矩阵组织：阶段、现有触点、Thinking（两类用户各自的判断）、Doing 时序、Feeling 把握感变化、设计痛点与机会点；阶段与各行五列严格对齐。两类用户画像放在顶部，Thinking 行用蓝 / 紫色点区分任务用户和学习用户，学习用户可从模糊兴趣或明确目标起步；不额外在阶段下重复“任务 / 学习”标签。Doing 时序由 beautiful-mermaid 排布，时间从左向右，两类开发者保留头像，Agent、开发环境、官方资料与社区用图标和文字呈现；五个角色标签与时序生命线对齐，标题独占行首。每阶段保留两条短痛点，分别映射后续设计机会。旅程不提前出现 Studio 的主动推荐、连线 Prompt、路径共创或认知卡。两条无数值曲线为设计推演。截图设计页复用黑底 §8；知识例证与服务图按图文 §14；原生翻页、概览、导航点、全屏和键盘运行时整套保留并补齐 hash 恢复。
