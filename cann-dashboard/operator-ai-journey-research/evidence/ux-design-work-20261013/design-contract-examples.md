# 五类规格的设计样例

日期：2026-10-13。以下是承接既有建设结论的**可评审草案**，没有安装为真实 Skill、创建 MCP 服务或改造任何平台运行时。用于说明 UX 如何与领域、工程、安全和测试共同把体验要求写进资产；技术字段与完成条件必须由相应 Owner 确认。

## 1. 发现合同：让方法或能力被正确选择

| 字段 | 应回答的问题 | 设计样例 |
|---|---|---|
| 任务与状态 | 哪种任务此时需要它？ | 首跑准备；构建失败；验证范围不足等，分别说明 |
| 适用范围 | 版本、环境和前提是什么？ | 由领域 Owner 提供适用版本、硬件、框架与必要输入 |
| 排除条件 | 何时不应使用？ | 环境不匹配、缺关键条件、已有更新方法时拒绝或转移 |
| 最小描述 | 怎样在目录中与其他能力区分？ | 用途、输入、输出与代价的轻量摘要；完整方法按需查看 |
| 来源与维护 | 谁维护，何时失效？ | 原文锚点、版本、Owner、更新时间与替代项 |

UX 工作：基于任务观察组织发现与比较；领域团队确认条件；平台适配发现/加载方式。验证：加入相近名称、旧版本、缺条件与不适用任务，记录误采用、漏采用和必要补问。

## 2. 执行合同：让授权与实际动作一致

输入至少区分目标、工作范围、环境、已尝试动作与必要权限。动作说明具体读什么、改什么、调用什么；对有副作用动作说明影响范围、成本和是否可恢复。

建议行为规则：

- 已确认的信息继续携带；只有影响下一步的缺项才补问。
- “解释原因”不能自动扩大为“修改文件”；用户更新意图后重新检查后续动作范围。
- 模板/脚手架负责提供代码或配置，Command负责发起意图，二者不混为一项能力。
- 同一内容内核按各平台入口适配；Plugin只是一种交付包装，不规定所有资产都必须经Plugin。
- 并行、依赖、超时、取消与幂等的实现由工程确认；UX定义用户需要理解的后果及干预时机。

验证：模糊意图、执行中改范围、拒绝授权、依赖失败和取消后续动作。不能仅以确认次数少作为成功。

## 3. 回执合同：让结果可判断、可审查

候选任务回执示意（这些不是 MCP 协议的通用必填字段）：

```json
{
  "task_id": "任务对象标识",
  "input_scope": "本次输入、文件或环境范围",
  "action": "实际完成的动作",
  "status": "verified | partial | blocked | unknown",
  "evidence": [{"type": "实际证据类型", "reference": "来源或产物锚点"}],
  "unverified": ["尚未检查的任务条件"],
  "next_actions": ["有依据的后续动作"],
  "owner": "技术结果或服务的责任角色"
}
```

`verified`必须对应明确的任务条件和实际证据，不等于工具返回无错误。MCP工具输出保留协议原有字段；领域适配器把结果关联到任务回执。UX与工程共同定义可理解的状态语义，领域/测试Owner决定哪些证据足以支持技术结论。

验证：典型样例通过但边界未覆盖、产物版本与证据不一致、部分执行、权限阻断。来源、适用条件与实际验证分开表达，不合成未经校准的正确概率。

## 4. 恢复合同：让失败保留可继续的现场

每类异常需说明失败事实、已执行动作、仍保留的现场、可否重试、补什么条件、谁接手以及如何返回。

- 权限不足：说明需要的范围，允许拒绝或改变任务，不把拒绝当用户犯错。
- 条件冲突：保留两种来源和适用性，先查证，不静默选一个。
- 重复失败：定义何种观察属于无进展；停止重复动作，提出取证或升级路线。
- 子任务失败或分歧：返回任务负责人，保留证据与未知项；分歧不以投票代替验证。
- 人工专家升级：携带任务、环境、日志、最小复现、已试动作和问题摘要；确认分享范围、责任与接续方式。人工专家与平台专职Agent分别定义。

验证：取消、超时、条件变化、跨任务切换及中断恢复后是否误重跑或遗漏现场。实现责任属于工程与服务Owner，UX检验可理解性、控制和连续性。

## 5. 完成合同：把系统结束与业务通过分开

领域与业务先确认任务成功条件、目标环境及必要证据。设计规格明确：

1. 哪些条件已验证，哪些只是推断或待检查。
2. “已生成”“已应用”“已执行”“已验证”的不同语义。
3. 模型结束、工具返回和运行预算耗尽分别怎样影响任务状态。
4. 未满足条件时怎样补测、继续或明确移交。
5. 交付后哪些内容可以授权进入团队交接或公共知识草稿。

任务内Loop根据观察继续或停止；最终验收仍由任务层规则与证据判定。学习目标另观察独立解释、延迟回忆或新条件迁移，不能用任务完成代替。

## 如何用于既有建设项

项目规则与知识优先核对作用域、适用性与来源；任务方法核对分支、停止、恢复与产物；模板核对生成范围与版本；MCP核对参数、授权、错误和证据；Agent协作核对委派与交接；Hook核对必要关口。按现有资产逐项审查已有字段和行为，缺什么补什么，不先假定所有资产都缺这些内容。

同一首跑任务按原建议先连接知识、方法、模板、实时工具和验证，再扩展编译/精度故障与协作。采用对照或任务回放判断每类规格的贡献，尚未开展真实用户或NPU实验。
