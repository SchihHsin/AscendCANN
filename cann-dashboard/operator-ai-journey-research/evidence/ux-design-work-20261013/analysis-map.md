# Agent 时代 UX 工作研究：分析推导与复用记录

日期：2026-10-13。副本：ux-design-work-in-agent-era.html。原研究 index.html 及两份行为报告保持原状态。

## 核心问题

Agent参与更多执行之后，UX设计师应介入哪些体验决定、交付什么，以及怎样与工程和领域团队验证？以既有沙盘建设结论为起点，展开各建设项怎样做。UI保持为必要交付之一。

- operator-ai-journey-deck/index.html:252–255原结论：先覆盖项目规则、可引用知识、MCP通用供给，再为Skill/Workflow、Command、Plugin/Extension、Custom/Subagent、Hook按平台装配适配。五平台口径不改写成当前市场验证。

## 完整沙盘的工作映射

| 能力/机制 | 体验问题 | UX介入 | 候选交付 | 验证 | 协作 |
|---|---|---|---|---|---|
| 项目规则 / 持久上下文 | 哪些约束应持续生效？ | 设计作用域、冲突优先级、更新与失效条件；让已确认事实可以纠正。 | 规则作用域图＋冲突与失效用例 | 跨目录／任务切换后，约束是否正确继承或停止 | 领域 Owner 确认规则；工程实现加载与隔离 |
| 领域知识库 / 检索源 | 什么信息适用于当前任务？ | 组织版本、硬件、来源与适用范围；定义缺项补问和冲突处理。 | 知识单元规范＋适用性与引用规范 | 旧版本、缺条件、矛盾资料是否被识别 | 资料 Owner 维护真实性；检索与数据团队实现 |
| Skill / Workflow | 何时采用什么方法？ | 从任务状态定义触发、输入、判断分支、停止／升级与产物。 | 方法流程＋Skill 行为规格＋场景集 | 适用时正确进入；不适用时拒绝或换路 | 领域专家提供方法；工程实现脚本与工具 |
| Command / Prompt | 一句指令委派了什么？ | 明确意图、范围、默认值、歧义追问及动作预览。 | 命令意图表＋补问与确认规则 | 模糊指令不越权，修改意图能及时生效 | 产品共同定义范围；工程实现解析与路由 |
| MCP / Connector | 如何安全地取得事实和执行动作？ | 定义参数补全、授权时机、可理解的输出、失败与下一动作。 | 调用体验合同＋状态与错误语义 | 超时、权限不足、部分结果可理解且可继续 | 服务团队实现能力；安全团队确定权限 |
| Plugin / Extension | 能力如何被发现、交付和更新？ | 明确包内能力、依赖、安装后的生效与关闭／升级行为。 | 能力交付蓝图＋版本与兼容体验规范 | 安装／更新／关闭后，状态和可用能力一致 | 平台与发布团队实现包、兼容和生命周期 |
| Custom Agent / Subagent | 谁负责什么，怎样交接与复核？ | 定义任务边界、最小上下文、证据回传、分歧解决与责任。 | 分工蓝图＋委派与交接合同 | 子任务不越界，分歧按证据解决，失败可回主任务 | 工程实现委派；领域专家定义复核标准 |
| Hook / Lifecycle | 哪些动作需要固定检查关口？ | 设计触发事件、检查理由、阻断／放行与恢复路径。 | 事件关口图＋拒绝与恢复规则 | 必要检查不会漏；无关事件不反复打断 | 工程实现事件与门禁；安全／测试确认约束 |
| Harness / Agent Runtime | 交互要求由运行时怎样兑现？ | 定义用户可理解的状态、控制需求、连续性与异常验收。 | 体验验收要求＋与工程共同定义的状态合同 | 任务状态与实际执行一致，中断后保留现场 | 工程拥有运行时／接口实现；UX联合验证体验 |
| Agent Loop · 任务内 | 何时继续、重试、停止或交还控制？ | 制定进展判据、重复失败处理、预算与停止／验收条件。 | 循环与退出规则＋异常轨迹用例 | 无进展不无限重试；模型结束不冒充业务完成 | 工程编排循环；领域／业务定义完成条件 |

Runtime/Loop普遍内置不等于UX不能提出体验要求，也不等于UX直接装配或保证正确。模板/脚手架是原资产分流里的代码配置形态，Command只是可能的发起面；Plugin不是必经层。

## 复用与新分析

- 复用：访谈、15条公开语料、三项检索记录、原建设结论、沙盘状态、三层边界、原型触发/恢复规则。
- 重释：六题作为任务案例，名称保持；平台产品形态与职业头衔不自动沿用为UX结论。
- 新增综合：体验归因、既定建设项的具体规格/交付/验证、协作关系与表达/行为贡献对照。这些为分析和待验证建议。
- 一手资料见primary-sources.md，支持研究方法与机制，不证明UX独占职责。HAX/PAIR未取得可核对正文，不作为本轮证据。
- 尚未完成：设计团队访谈、真人/真实任务对照、长期学习/社区回流数据、真实接入/NPU收益。

## 固定问题身份

01 可装配能力难以按任务选配并有效使用；02 开发者难以判断和选择下一步行动；03 生成结果的可信性难以验证；04 任务完成不等于开发者能力增长；05 团队难以共享完整的决策背景；06 从论坛发帖到与 AI 对话，问题与解答不再自然沉淀于社区。
