# 通用 Workspace 中的学习交互机制

## 设计判断

以任务为共同容器，以学习路径组织需要教学的部分。主动学习和开发中学习采用同一套三栏结构、节点组件、修改确认与结果回流机制。学习分类是任务的另一检索入口；普通任务不会因展开学习而被替换或复制。

本轮依据是用户已确认的产品方向与提供的三栏 Workspace 参考，属于 L 级设计提案，不作为 Ploy / Codex 的实际教学能力证据。

## 对象与状态

| 对象 | 携带内容 | 交互规则 |
|---|---|---|
| 任务 | 对话、项目、文件、环境、运行记录 | 切换材料不另开任务；保存进入学习前的文件、选区和工作位置 |
| 学习路径 | 所属任务、目标、节点顺序、版本 | 同一任务可从学习分类找到；对话与手动调整都先生成修改预览 |
| 节点 | 内容、练习、验证方法 | 确认路径后直接展示内容，不重新询问目标；随内容类型调整右侧布局 |
| 学习记录 | 已查看、已尝试、检查通过、跳过 | 看过解释不等于掌握，失败不能自动推进；跳过讲解保留验证 |
| 工程结果 | 实验副本、Diff、项目应用状态、运行证据 | 练习通过、应用项目和项目验证分别记录；修改项目须单独确认 |

## 场景 A：主动学习

左侧学习入口 → 中间表达目标 / 右侧浏览路径 → 右侧审阅草案 → 确认 → 讲解与维度演示 → 跟练 → 检查反馈 → 保存记录 → 下一节点。

没有项目时使用明确标注的示例环境。后续关联真实项目需重新核对环境与适用条件，不能把示例检查直接当成真实项目验证。

## 场景 B：开发中学习

原开发任务 → 对当前文件 / 错误提问 → 就地解释 → 用户选择跟练 → 审阅局部路径 → 复用场景 A 的学习节点 → 通过检查 → 回到原文件审阅 Diff → 确认应用 → 后续项目验证。

临时解释无需建路径。用户也可直接审阅修复，不必学习。未接受学习建议时，不修改路径、不创建学习任务、不打断开发操作。

## 主动性与用户控制

- 建议应说明依据，例如当前输入与模型签名不一致；不因单次报错判断用户能力不足。
- 用户选择“带我练习”之后，才形成局部学习路径。跟练使用隔离副本，原任务现场保留。
- 对话“跳过讲解”和手动“跳过”进入同一修改预览；确认后更新，保留练习和历史。
- 学习过程中允许回看解释、重复练习、暂不应用、回到代码。退出学习不会丢失工作现场。
- 生产实现应支持忽略建议、停止此类提示、任务上下文授权与项目敏感信息范围；当前 Demo 尚未实现这些完整设置。

## 原型范围

- 入口：`unified-workspace.html?scenario=learn` / `?scenario=dev`，报告第 17 / 18 页嵌入同一个实现。
- 支持两任务会话内切换、路径草案与跳过预览、对话关键词路由、维度动画、选择答案、错误提示、模拟检查、结果接续、项目应用与撤销。
- 顶部深色场景条属于演示控制，不是产品步骤栏。产品本身始终是左侧任务、中间对话、右侧产物。
- 全部文件、AI、测试和项目修改为模拟；没有真实视频、模型、NPU 执行或刷新持久化。代码编辑器为原有独立预览，其操作不影响新原型记录。
- 现有其他报告场景和竞品截图保留。本轮没有扩展竞品事实，也没有声称完整学习课程或工程验证已实现。

## 待验证问题

1. 用户能否分清“已看懂、练习通过、项目已应用、项目已验证”？
2. 在一次失败后，用户能否自行找到提示并完成修改？
3. 从开发进入学习再返回，是否仍知道原文件位置及剩余工作？
4. 学习分类作为第二入口，是否会被误解为新建了重复任务？
5. 三栏在嵌入报告时需整体预览，细节操作应展开完整尺寸；生产布局需进一步验证可调栏宽与阅读密度。

## 本轮检查

### Ploy 交互迁移补充

新增 `workspace-proactive.js`，通过“看建议与依据”与“主动跟进”进入，两个场景共用：

| 前期研究机制 | 本轮交互落点 | 边界 |
|---|---|---|
| 建议带理由，依据可打开 | 两项任务信号 → 打开路径或当前代码 | 不推断用户能力 |
| 预备行动 / 草稿 | 查看行动范围 → 接受打开路径 / 只看解释 / 暂不采纳 | 接受不等于自动执行 |
| 只读与写入权限分离 | 授权只读检查、暂停 | 不创建真实定时任务 |
| 夜间记录与返回简报 | 模拟离开返回 → 差异 → 适配草案 → 返回原任务 | 时间与快照均为预置演示 |
| Ploybooks 可复用规则 | 当前任务保存 / 停用“解释—练习—等待确认”规则 | 会话内模拟设置，未接自动触发引擎 |
| 后续效果观察 | 学习 / 项目状态对照、缺失证据、不相关反馈收起 | 无因果收益宣称，不扩大授权 |

依据沿用 `evidence/proactive/research-notes.md` 的官方来源索引；Ploy 的邮件案例仅准备草稿，发布权限与定时执行分开，GSC 有延迟效果观察窗口。以上为交互迁移，不代表 Ploy 提供上述学习能力。

新增检查：未授权返回不会生成后台完成记录；授权后能打开简报与草案；暂停、规则保存、不相关反馈、开发场景行动预览可操作。没有真实后台、跨会话保存或效果评估。
