# 任务内容管理：分类、收起与再次打开

2026-10-11 初稿 · 2026-10-12 更新。用户已授权采用“按任务问题分组 + 用途筛选”的方案整理并改 Demo；本轮核心交互已检查，待用户评审，文中规则是授权范围与验收依据，不代表验收已通过。用户最初提出：历史调用过的线索解释、误差核对、图像与张量讲解需要明确分类、收起、再唤醒的机制，同时降低管理负担。本稿独立于主动提示方案。

## 1. 初稿时的问题与观察边界（历史记录）

- 当前工作区顶部呈现已打开标签；本轮读取既有审阅页时可见线索解释、示例修改预览、尝试记录、示例范围复核四个标签。

- `useContentWorkspace.js` 关闭时移除 tabs 条目，但保留 visitedTabs；普通内容仍隐藏挂载，并按 taskId 隔离。这支持会话内保留现场，但用户找回它时仍要走通用材料列表。

## 2. 推荐原则：自动记在任务下，用户只决定当前看什么

每份解释、图解、代码副本、核对结果和参考资料自动关联所属项目/任务、触发它的对话或问题、参数/代码版本和产生时间。第一次打开/产生就登记，不要求额外“保存到材料库”。

区分两个对象：可继续操作的内容视图，以及已经产生的尝试/核对快照。重开视图恢复现场；看旧结果打开当时的快照；重新运行是独立的明确动作，不因重开而发生。编辑草案的自动保留不等于应用项目修改，检查结果保存也不等于工程通过。

任务内先显示最近使用/与当前问题有关的内容。系统生成用途分类用于筛选，用户不需要建文件夹、选分类或拖动归档。分类可作为元信息，不强制所有内容只能属于一个类别。

| 用途筛选 | 例子 | 管理要点 |
| --- | --- | --- |
| 理解 | 线索解释、图像与张量讲解、关联字幕/图解 | 保留关注点、阅读位置、视频进度；再次打开默认暂停 |
| 试改与修改 | 参数草案、尝试、示例/项目Diff | 当前草案与历史尝试分开；应用身份与取消状态明确 |
| 验证 | 误差核对、范围结果、形状/工程检查 | 每次结果有时间、输入/代码版本、范围；旧结果不被新结果覆盖 |
| 参考 | 实际代码、官方来源、日志/附件 | 来源与引用关系保留；固定参考不被下一步替换 |

这是检索和呈现分类，不是强制任务阶段。用户可以跨类使用同一对象，不以Skill/MCP或文件格式要求用户判断分类。

## 3. 2026-10-11 的两种前台组织方式（历史讨论，已被后续决策取代）

| 方向 | 当前工作区 | 历史找回 | 取舍 |
| --- | --- | --- | --- |
| A · 保留标签 | 保留用户打开的多个视图；标签过多进入溢出列表，可手动收起 | 统一任务内容列表，最近使用＋用途筛选 | 熟悉、方便手动切换，但用户仍要管理打开数量 |
| B · 当前内容＋固定参考（当时推荐，后被用户否定） | 默认只展示当前主内容，必要时保留用户固定的一份参考；历史不常驻标签 | 同一任务内容列表，最近使用＋用途筛选 | 少整理；但不能替代画布总览，需清楚显示当前对象身份和重新打开入口 |

两种方式都保留左项目任务、中对话、右按需内容；自由画布只是同一批内容的另一种摆放，不另建一套历史。画布只在用户主动组织/复盘时打开。

## 4. 2026-10-11 的收起规则（历史B提案）

1. 用户明确进入下一步（从解释进入Diff等）时，前一步退出当前可见区并保留到任务记录；当前主内容接续打开。固定参考继续可见。
2. 系统在后台生成新结果时，只更新所属对象/记录的未读提示；不替换正在阅读、编辑或核对的主内容，不把新结果加入一串常驻标签。
3. 用户可以“收起”当前内容；其含义是退出阅读/操作区，保留内容与现场。与删除记录、停止执行、取消提案分别处理。
4. 收起最后一个可见对象后，可关闭右侧工作区，将宽度还给对话；任务级“内容”入口仍可找到。入口的具体位置/视觉待评审，不另加常驻内容侧栏。
5. 不因停留时间、所谓任务阶段完成或AI推断自动收起正在看的内容。临时并排结束恢复原来的主内容/位置；固定参考不被自动收走。
6. 隔离草案可自动保留；正式项目写入继续经过Diff确认。关闭后台运行的视图不等于停止运行；用户明确停止后保留已有日志与取消状态。

## 5. 再次打开规则

- 就近：原对话结论/代码行/结果旁保留“查看图解”“查看核对记录”等对象链接，一次点击恢复原对象，避免用户先去猜分类。
- 统一入口：任务级“内容”列表默认显示已使用/已产生的内容；最近使用在前，可搜索或按理解/试改与修改/验证/参考筛选。未调用能力另由新增内容动作承接，避免混在历史里。
- 对话指令：用户说“打开刚才的误差核对”时，带回最相关的任务内记录；若有多个相近版本，先给简短时间/输入摘要供选择，不静默打开错误的一份。
- 恢复：保留阅读位置、参数、选中图中对象、草案、视频进度；视频重开默认暂停。若内容已变化，在“继续当前现场”和“查看当时快照”之间明确区别，不自动重跑/重新生成。
- 版本：旧核对对应的输入/代码发生变化时，仍能看旧结果，但标注对应当时条件、当前待重新检查；不能把旧通过状态映射到新草案。
- 任务隔离：默认只检索当前任务。跨任务复用需要明确来源及适用条件，不把图像流程与AddCustom线索串成同一故障。

## 6. 降低负担的判断标准

- 不要求手工归类、逐项保存或整理才能继续任务。
- 已打开内容数量不会随着每次解释/运行不断增加。
- 收起后仍有明确对象链接和一个统一恢复入口；关闭不让用户担心丢失。
- 再打开不改变参数/记录、不启动检查，不要求重新描述背景。
- 最近使用列表不在阅读/点选过程中突然重排；新更新以未读标记呈现。
- 普通内容与画布共享内容身份和记录；收纳仅是视图状态。
- 保存/恢复跨刷新现场属于需要新增的持久化能力，本轮只提出需求，尚未实现。无需把所有隐藏视图永远挂载才能保留内容状态。

## 8. 2026-10-12 修订：保留全貌，以画布总览管理

用户反馈：上一版仍不好管理；原画布可同时看到所有内容，且分类需要更具体。此前“当前内容＋固定参考”不能独立承担历史管理，§3/§4的前台推荐由本节修订。2026-10-12 用户明确授权按本节“按问题分组 + 用途筛选”整理并改 Demo；以下方案已成为本轮实施约束，主代理核心交互检查已完成，用户评审仍待定；检查范围与证据见§9，不得写成用户验收已通过。保留收起不丢、重开不重跑、现场/快照分开等通用规则。

### 8.1 总览与深入操作

- 保留任务内的画布总览，呈现本任务已调用/已产生内容及其关系。当前阅读、代码、浏览器、Diff等深入视图仍按需打开；同一对象在两种视图中共享身份/记录。
- 内容少时可以同时展开；内容多时显示自动分组的概要卡，仍能看到所有组和条目入口，提供适应全部、搜索/筛选及定位。无需靠无限拖动画布寻找历史。
- 点击卡片可深入，关闭深入视图返回原总览位置/缩放；普通内容页保留回到总览入口。系统不自动把新结果带到阅读中的画布位置、不抢编辑焦点。
- 画布继续允许移动/固定/缩放，系统自动排列负责初始可读结构，用户拖动不是整理内容的前提。画布不恢复为始终常驻的右栏默认模式。

### 8.2 两个分组方向（决策已确认：B）

| 方向 | 组织方式 | 取舍 |
| --- | --- | --- |
| A · 按用途分区 | 图解、试改、核对、修改、资料各为一个区 | 按类型查找直观，同一个问题的相关内容会分散 |
| B · 按具体问题分组（用户已授权采用） | 问题/关注主题为主组，各条内容保留用途标签，可按用途筛选 | 更容易同时看到依据、解释、尝试和结果的联系；主题从上下文自动产生 |

B中的主题组由任务问题/触发消息推导，不是额外项目/任务或学习组。用户可改名/纠正关联，不要求创建目录或逐条归档。跨任务不混合；AddCustom与图像推理分别保留总览。

具体例子（结构示例，不预设根因或新增已验证内容）：

- AddCustom · “尾块访问是否越界”：错误/线索、访问过程图解、参数尝试、范围核对、候选Diff、相关代码/来源。
- AddCustom · “当前输出误差来自哪里”：误差分布、样本/条件记录、误差核对、待验证解释。与尾块主题有关系时给对象引用，不把两者写成已证实的因果。
- 图像推理 · “图像如何变成模型输入”：RGB分层、HWC→CHW/NCHW、参数试改、输入形状核对和代码/文档。不同关注主题可在同一任务内独立成组。

### 8.3 更具体的用途分类

| 用途 | 例子 |
| --- | --- |
| 图解与解释 | 线索解释、访问过程、图像与张量讲解、视频关联图解 |
| 试验与试改 | 可调参数、示例演算、尝试草案/记录 |
| 检查与结果 | 误差核对、范围/形状检查、运行结果及对应条件 |
| 修改与交付 | 候选Diff、已应用的示例副本、导出/交付草稿 |
| 资料与来源 | 实际代码、官方文档、原始日志、附件及引用 |

这五类是用途筛选/轻标签，不是互斥目录；日志可作为核对证据，同一解释也可作参考。状态（未读/待核对/已有结果/已收起）与用途分别呈现；浏览器示例结果继续与真实工程/NPU状态分开。系统根据来源/操作推导分类，用户无需维护分类才能继续。

### 8.4 收起后仍可看见

- 卡片收起为概要：标题、关键结论/当前状态、条目/尝试数量；主题组可整体收起，保留组头和组内内容入口。收起不从画布消失，也不等于删除、停止执行或取消提案。
- 同一图解重开复用原对象；多次参数尝试/核对挂在该内容下，以次数/版本概要展示，按需展开当时快照，避免重复卡片无限增长。
- 明确进入下一步可接续当前深入内容，但不会从总览移除前一步对象；固定对象不自动收起。
- 再唤醒可通过总览卡片、原对话对象链接或对话指令；恢复阅读/参数/关注点等现场，重新运行独立操作。

### 9.1 对象登记与共享身份

- [x] 内容首次打开或由演示动作产生时，自动登记到当前任务的内容总览；不要求用户先保存、选分类或建组。

### 9.2 总览、收起与深入操作

- [x] 任务总览按具体问题/关注主题分组；五类用途仅用于筛选或轻标签：图解与解释、试验与试改、检查与结果、修改与交付、资料与来源。用途由对象来源/操作自动推导，不要求逐项手工归类。本轮显示一个主用途，跨用途引用保留同一内容ID；多标签纠正入口未实现。
- [x] 总览展示全部主题组及可定位的条目入口。内容量增加时可折叠组、搜索/筛选和聚焦条目，不要求用户在无限画布上拖动寻找。
- [x] 卡片/主题组收起时保留可读概要（主题/内容名、关键结论或状态、条目/尝试数量及入口）；收起不删除对象、不停止后台运行、不取消提案。
- [x] 从总览深入普通内容后，返回动作回到原总览的滚动位置、缩放/摆放位置和聚焦对象；自由摆放视图仍供用户主动组织，不作为日常找内容的唯一方式。
- [x] 正在阅读或编辑时，后台结果只更新关联对象并显示未读/状态提示，不切任务、不抢焦点、不替换当前内容、不强制滚动。

### 9.3 记录、Diff 与恢复语义

- [x] 尝试/核对记录和 Diff 快照嵌套在来源内容/主题下，显示对应时间与条件；旧快照在新尝试后仍可查看，不覆盖、不伪装成当前状态。
- [x] 输入、参数或代码条件变化时，旧检查/核对结果仍标识其原条件，并提示当前条件待重新检查；不能把旧“通过”直接赋给新条件。
- [x] 打开或恢复对象只恢复原内容、位置、参数/关注点/讲解进度和记录，不触发 prepare、重新运行、检查或生成；重新运行必须由用户显式发起。
- [x] 关闭普通内容是离开当前视图；收起是减少总览中的展开细节；取消运行/取消提案是独立动作，不能由关闭或收起隐式触发。

## 10. 2026-10-12 再修订讨论：默认聚焦当前内容，按需看全貌

### 10.1 用户反馈与当前范围

用户认为用途分类与普通内容/总览/自由摆放的多种入口增加选择负担，提出：默认一个空间，在其中体现分类，可以缩小看总览并定位到需要的内容，也能直接缩小看到全部。本节将此要求与前轮未实现项一起讨论。**本轮不改 Demo；以下具体规则与默认焦点仍待用户讨论确认。** §9和实施状态清单继续描述现有代码，不能把本节方案写成已实现。

### 10.2 同一个空间随距离改变呈现

建议保留左项目任务、中对话、右按需内容。右侧日常入口统一为当前任务的一个内容空间，去掉要求用户先判断“普通视图/总览/自由摆放”的模式选择。

| 距离 | 同一对象的呈现 | 用户操作 |
| --- | --- | --- |
| 聚焦当前内容 | 正常字号的图解、代码、参数、视频或 Diff；当前操作和结果紧邻 | 直接阅读/调参/审阅；内容内部滚动 |
| 看同一问题 | 相关解释、尝试、检查、修改以可读概要呈现，保留标题/状态/记录数量 | 看联系，点对象直接聚焦 |
| 看整个任务 | 问题主题组与内容概要，一次露出全部；当前、未读、待处理位置可辨 | 找到主题/对象，点选进入；一键回到刚才 |

这三种呈现对应同一条缩放操作，不新增三个 Tab 或模式。正文和操作控件在聚焦时正常显示；拉远时逐步换成概要，概要保持可读的最小字体与点击范围。不能依赖把所有正文一直缩成小字来实现全貌；大量内容时先按问题显示全量组与条目入口，组内细节按需展开。

日常保留直接的“看全部”“回到刚才”；手动缩放/触控板捏合为可选操作，百分比和空间整理可放次级工具，不要求掌握手势或拖动对象才能使用。默认普通滚轮负责当前内容滚动，不意外变成缩放。第一次使用可在“看全部”旁给一次简短提示，不弹强制教学。

### 10.3 默认焦点的两个候选（产品默认规则，非用户日常模式）

- **A：进入任务聚焦当前内容（推荐）**。第一次打开问题时对焦当前相关材料；再次进入恢复上次阅读/操作现场。看全部才拉远，点内容再对焦。对当下任务行动更直接。
- **B：进入任务先看全貌**。所有主题先出现，点一个再操作。适合复盘/交接；高频任务会增加一次选内容，因此不建议作为日常统一默认。

右区按需出现；没有内容需要查看时可整体收起。用户主动选择复盘或看全部可以对焦全貌，不需要另外选一种工作区模式。

### 10.4 分类作为空间中的线索

- 主分组按具体问题/关注点命名，例如“尾块访问”“输出误差”“模型输入布局”。同一问题的依据、图解、尝试和结果放在一起；状态不预设根因已证实。
- 五用途保留为对象的轻元信息/图标：解释、试改、检查、修改、来源。日常不常驻五个筛选按钮、不要求先选用途才能打开。搜索在用户找内容时使用，用途筛选可收进搜索结果，不替代空间定位。
- 分组自动登记，用户无需手动归档。组名/归组纠正属于对象或组菜单的可选动作；不能增加每次生成后的分类确认。含义不明确时暂留当前问题，之后可纠正，避免错误语义分组被当成真实判断。
- 同一对象具有多个用途时保留一个身份；相关主题引用该对象，不反复创建相同图解/结果。跨主题连线只在选择/悬浮时局部显现，不让全貌成为密集线网。
- 尝试、核对、历史提案叠在所属内容下，显示“当前条件＋历史数量”。看某次历史才展开其时间/输入/代码条件，不为每次操作扩展一张同级卡。

### 10.5 主动交互如何进入同一个空间

- 明确问为什么：回答与相关内容同步准备；按用户意图对焦相应图解，不要求选类别或显示方式。
- 只报告失败：短依据与就近深入入口出现，保持当前镜头；用户决定理解或补证。
- 调参：图形、示例代码、本次结果在原对象更新。下一动作贴结果出现，处理后留状态摘要，反复改参数不反复弹提醒。
- 明确要采用：在当前问题范围展示 Diff，相关尝试依据可就近查看；确认应用只改变被确认副本，应用不自动检查。
- 明确检查：检查结果归到同一问题和对应对象；示例结果、真实工程待验证及旧条件分开。
- 正在阅读/编辑时，新内容只登记并显示轻更新提示，不移动当前镜头、不重排用户正在看的对象。用户明确发起新操作才接续对焦。新对象落在组内预留区域，内容增长后仅在明确“整理”时重排。
- 提示仍沿用B方案：浅蓝紫、黑主按钮、一次短强调、处理后摘要。两案例用同一触发/退出规则，不增加另一套提示管理入口。

### 10.6 前轮待做项随本方案重整

| 待做点 | 在单一空间中如何处理 |
| --- | --- |
| 整个右区收起/唤醒 | 收起整区归还对话宽度；任务边缘保留一个轻入口，重开恢复原镜头与内容，不重跑 |

| 固定参考 | “留作参考”在下一步仍可就近对照；统一其身份与恢复。自由画布“锁定位置”是另一个空间操作，不能与工作参考混用含义 |

| 跨任务复用 | 用户明确引用时保留来源与适用条件，再登记到目标任务；不自动混合两个任务 |

### 10.8 用户补充：由体验判断形式，并精简两处标题栏

用户进一步明确：“缩小看全部”只是思路，无需机械照做，可以选择体验更好的形式；附图指出 `header.tw-header` 和 `header.panel-header.conversation-header` 是否必要，认为降低屏效。本次仍先讨论修订方案，未改 Demo。

**当前界面观察（M）**：原浏览器自然宽度下布局为窄屏，不能同时判断两个桌面标题栏。为查看指定两处桌面结构，临时1280×720截图并读取DOM尺寸，随即恢复浏览器默认尺寸，未刷新/导航/操作任务。对话标题栏62px，工作区标题58px、标签37px、操作栏34px，右侧三排共129px。截图已保存并查看：`ascend-studio/evidence/20261012-header-review/02-desktop-headers.png`。这只是标题层级观察，不是新功能验收或完整交互/无障碍测试。

两个结构方向（供讨论，不新增给产品用户的模式选择）：

| 方向 | 具体处理 | 判断 |
| --- | --- | --- |
| A：合并重复标题/导航（推荐） | 全局顶栏呈现具体任务身份；中间取消独立“对话”标题带，新对话/历史/导出挂任务对话菜单；右侧将工作区标题、当前标签、通用操作合成约32–36px一条紧凑栏，保留当前内容身份、看全部/回到刚才、收起与更多 | 身份/操作位置稳定，减少重复层级，右侧预计释放约90px。保留有名称的操作入口与键盘访问，不能为了省空间只剩无提示小图标 |
| B：取消所有栏，操作悬浮在内容上 | 标题由内容自身表达，全部公共按钮在空间边缘悬浮 | 可多获得少量面积；窄栏可能遮住图解/代码，固定控件位置与操作可发现性较弱，不推荐作为日常默认 |

推荐交互进一步收敛为：**默认自动聚焦当前内容，以正常尺寸直接阅读/操作；“看全部”自动呈现同一任务的问题组/概要；点对象自动对焦，“回到刚才”恢复现场。** 用户无需手动将缩放调到合适比例，连续缩放可保留为辅助。长代码/Diff/视频内容内部按正常方式滚动；看全貌时显示可读摘要，不把整份正文不断缩小。分组、历史与对象身份连续保持。

现有“内容总览/返回总览/在画布中整理/自由摆放”等公共入口应按这一行为合并，空间整理放次级菜单。缩放操作无需成为使用的前置动作，整个右区也可收起/唤醒。任务对话中的新对话与左侧新建任务语义不同，不能直接合并导致记录丢失。原装饰底图若依附将删除的标题栏，可融入对话内容背景，不因此增加新的占位区。
