07 · AGENT SUPPLY　MCP 提供连接能力，Skill 说明过程，应用层负责验收
01任务上下文
用户目标目标 · 环境 · 错误
task: 首次构建 Ascend C
cann: 8.2 · chip: 910B
OS / framework / error: 可选

建设 任务入口约定 Agent 所需的最小上下文：目标、版本、芯片、系统和已有错误信息。

使用 Skill 据此判断是否适用；关键环境字段不全时先补齐或停止，不臆测。

02Skill 组织方法
SKILL.md触发 · 输入 · 核验
name: cann-first-run
Use when: 首次构建样例
Inputs: CANN / chip / OS
Steps: 查兼容 → 准备样例 → 验输出
Stop: 版本不明或前置条件不满足

建设 每个 Skill 聚焦一种任务，注明适用版本、预期信号、失败分支和停止条件。

使用 Host 在任务匹配时加载步骤；Skill 说明何时查、按什么顺序做，不承载实时资源数据。

03MCP 连接知识与工具
Resources
+ Tools静态知识 · 实时查询
Resource: cann://docs/{id}/{version}
返回正文 + source_url + applies_to

search_resources(query, version)
get_compatibility(cann, chip)

建设 Resources 提供稳定文档与版本；只读 Tools 负责检索 / 兼容查询，并返回来源和适用范围。

授权 预检、构建等会改变环境的 Tool 单独授权，并记录调用者和执行结果。

04结果形成应用回执
Evidence
Receipt验收 · 恢复 · 接手
status: passed | failed | not_run
version: CANN 8.2 · 910B
source_refs: [原文 URL / 锚点]
error_code: 可选
log_excerpt: 关键片段
artifact_url: 报告 / 产物
next_action: 复查版本 / 重跑

建设 回执携带状态、引用、日志、产物和下一步；应用服务定义验收字段。

判定 not_run 表示未执行 / 缺验证；failed 表示执行失败 / 结果不符；预期信号与产物齐全才标 passed。

边界 MCP 返回结构与业务验收回执分开，回执字段属于应用层设计。

开放顺序先发布带版本的只读 Resources / 查询 Tools→明确 Skill 成功与停止条件→再逐项开放需授权的执行动作not_run / failed / passed 属于应用层状态设计
