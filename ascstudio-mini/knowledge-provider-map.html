KNOWLEDGE SUPPLY · TARGET BLUEPRINT

让知识被找到、被调用，
也能被验证。

课程、路径、认证、知识点和活动只是体验入口。供给侧需要把官方资料、学习资源与实践证据编成有版本、有边界、能被不同 AI 工具消费的服务。

核心判断

不是多放几个 AI 文件，而是建立一个可信的知识内核，多种可发现、可调用的交付通道，再用使用和验证证据推动更新。

01 / SUPPLY CHAIN

从内容资产到学习服务的一条供给链

所有渠道读取同一套知识目录与治理规则，避免各做一份、各自过期。

04

体验与证据回流

让推荐能解释、结果能复用
按目标与任务上下文检索 / 推荐按芯片、版本、基础过滤不适用项展示来源、适用范围与验证状态收集收藏、完成、无结果与纠错

每份知识都要带上“可用边界”

Knowledge Unit · 最小发布单元

身份与类型ID、标题、语言、资源类型（课程 / 概念 / API / 错误 / 案例）
适用条件CANN / 芯片 / OS / 框架版本、前置知识、适用 / 禁止触发条件
方法与判断结论、步骤、预期信号、停止条件、关联项与冲突 / 替代关系
可信与维护原文锚点、许可、Owner、最后验证、更新时间、失效版本与退役状态
无边界就不硬答版本或环境不明时返回 unknown / 先补问；不要把整页切块就当成已验证知识。

接口各司其职，不互相替代

发现 ≠ 内容 API ≠ 工作流 ≠ 执行动作

robots.txt + sitemap爬虫规则与 URL 发现。robots 不是鉴权；受限内容仍要由服务端认证。
llms.txt + Markdown给 Agent 的精选目录与干净正文。llms.txt 是提案，不保证每个模型读取。
JSON-LD / Schema.org标明课程、活动等页面类型。帮助机器理解页面语义，不替代完整内容。
REST + OpenAPI产品调用的稳定服务合同。检索、详情、兼容、推荐、进度可按需提供。
MCP Server标准化连接。Resources 放内容，Prompts 给模板，Tools 调服务；先只读，写操作再做授权。
Agent Skill可按任务加载的方法包。写清触发、输入、分支、停止、验证和产物；不复制整座知识库。

P2任务型 Skill、只读 MCP；再按权限扩展执行与评测闭环
