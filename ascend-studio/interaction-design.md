## 设计点 01：按用户意图决定主动展开程度

| 用户当前行为 | 系统响应 | 展示规则 |
|---|---|---|
| 明确问“为什么、怎么理解” | 短回答与相关图解直接一起出现 | 带入当前代码、错误和输入；保留原任务与对话，不要求先找材料或打开画布。 |
| 只报告失败、要求修复 | 先给简短判断依据，再提供贴着当前问题的深入入口 | 解释入口与本次诊断相连，不自动展开完整讲解或强制插入学习步骤。 |
| 正在阅读或编辑 | 保持当前位置，新建议先轻提示 | 保持当前材料、滚动位置和编辑状态，避免后台新内容突然替换正在看的内容。 |
| 表达“试一下、采用、检查” | 直接接续对应操作 | 根据明确意图带入相关参数、修改审阅或原任务检查；不额外要求选择材料类型或显示模式。 |

这四条由用户在本轮批注中明确要求作为设计点记录。主动性随当前意图变化，避免所有场景都套同一种自动展开行为。

## 设计点 02：图解内直接试改，结果就地更新

用户已选择：图解展开后，少量参数直接可调，结果留在原处更新。

- 参数变化只作用于当前示例/隔离副本；真实项目修改保持独立的审阅与确认。
- 图形、相关代码示例和当前结果使用同一份参数状态，不要求用户手动整理画布。
- 图解与反馈继续围绕当前任务的问题展开，不另起学习中心或独立学习任务。

## Demo 中的接续

- 两个任务的初始对话明确提出理解疑问，因此进入任务时同步呈现相关图解；实际只读代码仍可按需打开。
- 图解内直接调参，图形、对应代码与当前演算联动。即时反馈与已保存尝试分别显示，保存不会自动切换材料。
- 明确说“采用”或点击“审阅当前修改”时，从当前参数生成示例 Diff；取消返回图解，保留参数和尝试。应用仍需明确点击确认，只更新浏览器副本。
- 确认应用后保持当前审阅页，不自动运行检查。用户明确说“检查”时，已应用副本进入分层复核；尚未应用时检查当前算例。明确要求实际代码或误差核对时进入相应只读来源或证据内容。
- 对话正在回看时，新记录或答复不自动滚到底，用“有新回复”提示。右侧新增结果仅提示未读，不抢当前材料；答复等待期间切换任务不会把用户拉回上一任务。
- 字幕追问保留片段时间、原句和图解关注点；调参暂停讲解，继续播放可直接恢复讲解，当前试改参数保留。视频仍是动态讲解示例。
- 恢复原始参数保留尝试和已应用副本。任务往返保留各自现场；刷新仍恢复默认，没有新增持久化。

应用后不自动检查，用户明确检查才执行，已在本轮实现中确定。真实项目 Diff 映射与工程检查接入仍需后续设计和实际环境支持。当前不把浏览器示例通过当作项目完成。

### 两套候选池与排序

**学习模式：**

- `L1 概念补足`：结构化练习记录显示当前轴序/维度错误；后续同条件通过后撤下。
- `L2 依赖补学`：存在明确学习目标/路径，下一练习所需前置理解尚未完成；引导至相关概念。
- `L3 迁移挑战`：当前有效学习小结或基础练习已完成，且没有对应迁移练习；用不同输入练习。仅看过或完成一次不等于掌握。

当前目标及卡点/前置优先，迁移挑战其次，最近记录只用于同分排序。同一开发问题只有与学习目标相关或用户明确求理解时才进入学习池；当前开发 task 不再固定100分占位。

**开发模式：**

- `D1 排障推进`：有明确未解决失败现场及相关线索；标题写具体问题与待查方向，不断言根因。
- `D2 验证缺口`：已有演算/改动，但缺少与当前代码版本和条件对应的验证记录。例如仅浏览器示例时建议对照实际循环；缺边界 case 时建议补检查。
- `D3 变更复核`：已有输入约定/示例与上次验证 snapshot 不一致时，提示复核受影响内容；没有可靠 snapshot 就不产生此类建议。

排序为阻塞问题、验证缺口、变更影响；最近记录仅同分排序。两模式各最多3条，不设每类固定槽位；无有效事项时显示弱空态，不以最近任务补位。

候选在首页进入和已有任务事实变化时刷新，不增加定时监控。切换学习/开发时取对应候选池，保留目标输入与附件，清除展开卡状态。

- （历史决策，已由 2026-10-27 的“跨任务画布节点与关系语义”更新替代）AddCustom 曾保留四个业务分组；当前以真实问题起点、材料依据和流程节点关系表达，不再绘制抽象背景分区。

## 训练调优字段组合：悬浮停留连线（2026-10-26）

- 组合首页默认仍是 28 个未选字段、零连线和空 Prompt；下述交互只在用户开始悬浮探索后发生。
- 鼠标停留字段约 280ms 后，该字段成为连线起点并以节点圆点的浅色晕表达。鼠标移开起点时，细虚线从起点沿指针方向预览；进入另一字段时预览线吸附到该目标，并出现环形停留进度。
- 指针在目标字段停留约 680ms 后固定关系、把两个节点加入可编辑 Prompt，并将目标字段作为下一条关系的起点，形成 A→B→C 的连续路径。移开候选目标会撤销该次目标计时，可以继续选择另一个目标。
- 点击画布空白处、离开画布或按 Esc 会取消整段待连线预览。点击节点加入 / 移除单独 Prompt 字段与 Alt+Enter 键盘连线继续保留；没有添加可见说明标签。
- 定时回调同时校验计时世代和鼠标当前命中的字段；即使离开后快速回到同一字段，旧回调也不能确认连线。实现依赖 pointer enter / move / leave，不依赖按住鼠标键；移除画布的 `touch-action: none`，避免组合页阻止触屏纵向滚动。

## 2026-10-27 · 跨任务画布节点与关系语义

本节更新并替代此前“AddCustom 画布保留四个业务分组”的临时决定。用户指出“现场与来源 / 理解与试算”等标签把不同层次的概念混为一组，且 ResNet50 画布没有对应结构。

- **公共语义**：卡片必须承载一个真实的任务上下文、材料、判断、动作或结果；连线只表达明确的来源、支撑、推进或核对关系。不得仅为归类方便创建背景分组。只有多个同一目标下的真实子流程确实需要归拢时，才使用分组。
- **材料与动作分层**：代码、文档、运行记录等可以作为独立卡片阅读，但语义上是支持某个判断 / 动作的依据，不应伪装成与操作阶段并列的业务分组。单独显示的材料卡须用可解释的关系连接到所支持的节点。
- **AddCustom**：以“问题现场”（任务简报）作为旅程起点，连接代码与已知现象；来源代码 / 证据 / 文档关联到线索解释。之后按“线索解释 → 参数与范围策略 → 对照试算 → 修改草案 / 差异 → 范围复核 → 误差核对 → 复核记录”表达过程。移除四个背景分区，不再使用“现场与来源”“理解与试算”“修改与核对”“输出误差与复核”作为画布组名。
- **跨任务适配**：图像推理继续按图像 / 张量理解、预处理练习、形状结果与核对的实际关系展开；ResNet50 继续按官方学习阶段与学习步骤组织。统一的是节点与关系的表达语法、公共控件与卡片操作，不统一各任务的内容分类或流程名称。
- **对象导航栏**：TaskCanvas 删除画布上沿的选中项名称 / 直接关联芯片横栏。画布关系由卡片连线表达；节点聚焦 / 放大等操作留在卡片右上角；内容总览、临时对照、缩放、平移、适应全部和位置编辑留在公共 CanvasToolbar。节点关系详情仍可在内容详情中按需查看。
- **持久化**：默认新节点位置按当前内容关系设置；升级布局时只补齐缺失坐标，不覆盖用户已保存的自定义位置。AddCustom 增加“问题现场”节点时，合并到旧画布状态，不清除已有内容或手动布局。

本轮实现基于本地预置材料与明确关系数据（H），不声称真实代码、精度或 NPU 验证。页面序列和 API / Protocol、Host / Harness、Application / Task 边界不变。

## 2026-10-28 · 跨任务画布节点语义契约（实施基线）

用户确认将“统一画布节点语义”纳入修改。本节将 2026-10-27 的原则展开为可供组件与数据适配器执行的契约；统一语义字段与可复用行为，不把 AddCustom、图像推理和 ResNet50 画布压成同一组业务分组、同一种布局或同一套状态判定。

### 目标与边界

- 用户跨任务看到节点时，应能通过稳定的标题、摘要、内容类型、状态和关系，理解“这是什么、当前怎样、与什么有关、可以做什么”。
- 每个任务继续由自己的内容模型解释业务意义。公共层负责标准化呈现，任务适配器负责把领域数据映射到标准字段、标准关系和标准状态；不得让公共组件猜测根因、完成条件或节点关系。
- 关系必须来自数据中的显式声明或任务规则可复核的状态推导。节点靠近、同色、同组或先后渲染不能作为关系证据。
- “分组”不是必需的节点字段。只有业务本身存在真实阶段、目标下的子流程或有名称的集合时才提供；不得为了视觉均匀或便于分类而新增背景分区。
- 画布结构、关系、可见性和视口行为不改变学习顺序、开发执行顺序、任务状态或真实工程文件；演示中的预置判断和本地模拟结果必须标明其适用范围。

### 公共节点契约

所有可呈现在画布上的对象都应能归一为以下语义。领域字段可以保留；公共组件只依赖标准化后的字段。

| 字段 | 必需性 | 用途与约束 |
| --- | --- | --- |
| `id` | 必需 | 任务内稳定唯一；版本快照和历史记录使用独立 ID，不能复用当前材料 ID。 |
| `title` | 必需 | 用具体名词或动作说明对象；避免只写“内容”“结果”这类无上下文词。 |
| `nodeType` | 必需 | 稳定的语义角色：`goal`（目标 / 问题起点）、`step`（流程或学习动作）、`material`（代码、文档、图解、视频等依据）、`evidence`（现象、日志、测量或引用）、`action`（可执行试改 / 操作）、`result`（尝试、检查或学习产出）、`note`（用户补充）。它表达“对象是什么”，不是颜色或组件外观。 |
| `contentType` | 必需 | 阅读/交互内容形态，如 `code`、`document`、`diagram`、`video`、`diff`、`checklist`、`note`、`drawing`、`summary`。内容形态不替代 `nodeType`：一个 `material` 可有多种内容形态。 |
| `summary` | 有则优先 | 一句话说明当前对象的关键内容或意义；不能把完整来源、推理链或结果边界都塞进标题。 |
| `status` | 适用时 | 使用任务适配器映射出的通用状态之一：`available`（可查看 / 可开始）、`in-progress`（正在进行）、`proposed`（待采纳 / 待审阅）、`completed`（此对象声明的目标已完成）、`needs-review`（还需核对）、`blocked`（有明确阻塞）、`outdated`（依据条件已变化）、`archived`（已收起归档）。没有状态就省略；不得为填满视觉样式制造状态。 |
| `statusLabel` | 有状态时 | 面向用户的具体中文状态。公共状态供组件处理，标签由任务适配器给出，例如“待确认”“示例范围内通过”“输入已更新”；不能将所有完成都写作“已验证”。 |
| `provenance` | 对依据 / 结果必需 | 来源、生成方式、时间 / 版本或适用条件。至少能回答它来自哪里；模拟、推导和真实运行需可区分。 |
| `parentId` | 有真实包含 / 层级关系时 | 指向实际父节点，例如 ResNet50 阶段与学习动作；不用于单纯的视觉摆放锚点。 |
| `groupId` | 可选 | 只标识真实业务分组；没有真实分组时不创建。不能与 `parentId` 混用。 |
| `relations` | 有关联时 | 显式的定向关系数组（定义见下节）；来源、目标和关系理由均可追溯。 |
| `domain` | 可选 | 任务适配器标识，用来选择领域状态和字段解释；不直接显示为无意义标签。 |
| `viewState` | 仅 UI 层 | 可见 / 收纳、折叠、聚焦、固定、选中、坐标、尺寸等用户视图状态；不得写入业务 `status`。 |

便签、手绘等用户新增对象仍使用同一契约：`nodeType: note`，内容形态分别为 `note` / `drawing`，并可用 `parentId` 或 `relations` 表达用户明确创建的上下文关联。新增对象不应自动继承业务状态或伪装成任务阶段。

### 公共关系契约

边统一为 `{ id, fromId, toId, relationType, label?, evidence?, conditions?, status? }`。`relationType` 仅使用下列语义；若现有业务关系无法准确映射，优先新增有明确定义的关系类型或不连线，不能映射成含糊的“相关”。

| `relationType` | 含义 | 适用示例 |
| --- | --- | --- |
| `contains` | 结构性包含 | 学习阶段 → 该阶段的学习动作。通常由 `parentId / children` 派生。 |
| `precedes` | 明确流程先后 | 学习动作序列、已经确定的处理步骤。不能只按卡片位置推断。 |
| `derived-from` | 目标对象由来源对象或特定快照生成；边仍按来源 → 结果绘制 | 所选尝试快照 → Diff；原始材料 → 自动生成的摘要。 |
| `supports` | 材料 / 证据支持某一判断或动作 | 文档、代码、日志 → 线索解释或待执行动作。 |
| `checks` | 检查针对的对象 | 范围复核 / 精度核对 → 指定版本的示例或输入快照。 |
| `supersedes` | 新版本明确替代旧版本 | 新提案取代上一提案；需要保留两个版本身份。 |
| `references` | 可追溯的来源引用，不声称支持或验证 | 官方资料 → 学习节点；代码锚点 → 解释节点。 |
| `related-to` | 业务上明确相关但不属于上列 | 仅在领域规则能说明关联依据时使用，必须填写可见 `label` 或 `evidence`。 |

- 连线方向遵循“来源 → 结果 / 受支撑对象 / 被检查对象”；图形关系不代表业务通过、因果确认或执行完成。
- 快照类边必须保留具体快照 ID 和检查条件；当输入、参数、代码版本或范围变化时，由适配器将旧结果标记为 `outdated`，不得继续展示为当前版本通过。`outdated` 表示依据已变化，采用提醒色，不等同于执行失败。
- 结构层级可由 `parentId` 呈现为树；顺序由显式 `precedes` 或领域排序键表达。卡片拖动只改 `viewState.position`，不改变结构父子和业务顺序。
- 关系标签使用短而具体的中文，如“依据”“生成自尝试 2”“检查版本 v3”“课程步骤”；不要把内部枚举名直接暴露给用户。
- 关系进入总览连线前必须通过共享 relation normalizer；缺少明确端点或使用未知类型的旧引用只能保留为导航入口，不得绘成边。

### 公共状态与来源边界

- 语义状态与卡片操作状态分离：`status` 表示任务对象本身，`viewState` 表示用户如何查看 / 管理它。隐藏、折叠、固定、聚焦、选中和放大都不改变业务状态。
- `completed` 仅能由任务适配器依据明确完成条件计算。ResNet50 的学习动作可依本地理解 / 练习 / 检查状态汇总；不代表真实设备执行成功。AddCustom 的“范围检查通过”只表示所选浏览器算例的索引范围满足条件，不表示根因已确认或真实 C++ / NPU 精度已通过。
- `needs-review`、`proposed`、`outdated` 与 `completed` 不可互相替代。已有修改待审阅、使用旧条件的验证、材料可用、任务完成要分开表达。
- `provenance` 的展示强度应与证据等级一致：官方材料、用户提供的代码 / 日志、本地演算、浏览器模拟和真实运行不混写。未验证的来源或条件保持未确认，不以颜色暗示确定性。

### 画布的公共交互及任务适配

1. **发现与定位**：画布内容索引与“全部内容”视图读取同一份归一化节点 / 关系数据。点击索引定位节点；画布内聚焦只改变视口，不收纳关联节点；完整内容阅读离开画布到任务内容区。返回时恢复同一节点和原视口 / 布局。
2. **收纳与恢复**：收起、隐藏、恢复只改 `viewState`。收纳的对象仍在内容索引 / 全部内容中，可回到原坐标；新增用户对象也可通过同一入口找回。
3. **编辑画布**：移动、固定、折叠、尺寸和自由绘图操作只编辑呈现状态；不能重排 ResNet50 学习树或改变 AddCustom 的 attempt / diff / validation 版本关系。用户新增笔记仅新增节点，不悄然改变正式任务内容。
4. **卡片内容**：共用已有的标题、摘要、状态、来源和右上角操作位置；短内容尽量完整显示，过长内容遵守统一卡片尺寸与内部滚动规则。统一语义不意味着每类节点套同一视觉模板；代码、视频、Diff、学习步骤可按内容类型使用合适的呈现器。
5. **关系呈现**：全貌模式展示真实父子 / 推进 / 证据 / 检查边；局部聚焦保留与焦点直接相关的边。小地图按可见节点与真实关系范围绘制，不以未渲染的推测关系补线。
6. **适配责任**：公共 Canvas Shell 提供节点容器、统一操作语义、关系渲染、索引和视口持久化；每个 Task Adapter 提供节点映射、领域关系、状态计算、来源信息、关系标签和任务专属内容 renderer。任务适配器未提供语义时，公共组件不自行按标题 / 文案推断。

### ResNet50 当前学习步骤的内容排布

- 当前选中的学习步骤是关联内容的锚点；阶段 / 步骤树继续承担路径导航，内容卡不是额外的学习步骤。
- 图解、视频与章节控制、当前同步讲解是三张独立材料卡，默认横向并列；官方来源只在同步讲解卡内以折叠来源区呈现，不在视频卡或步骤卡重复。卡片顺序表达并列材料，关联线均从当前步骤连接。
- 动手练习和可回答的理解检查属于操作，排在材料行下方并各自拥有操作卡。理解题使用 `action / interactive`，其通过 / 未通过和检查解释属于该卡的结果状态；只有被单独保存、需要跨步骤引用的检查快照才作为 `result` 节点。
- 窄视口保持画布中的横向关系；由画布平移、缩放和小地图到达卡片，不把材料与操作挤成一条长竖列。卡片仍遵守共享的内容完整度、760px 上限、单一内部滚动区与键盘可达规则。
- “全部展开”用于看学习路径全貌，仍以完整学习步骤卡呈现图解、讲解、资料、练习与理解检查；它不改变普通画布中材料 / 操作卡的独立语义。

### 改造次序与验收清单
