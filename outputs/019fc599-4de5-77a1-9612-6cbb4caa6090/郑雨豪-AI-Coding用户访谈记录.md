## 访谈主题

围绕近期真实经历回顾人与 Agent、资料与环境之间的协作；不要求受访者现场执行任务。

## 一、用户基本信息

- **AI Coding 使用时长与频率：**半年左右，每天都用。
- **过去三个月使用的工具：**Cursor、Trae。
- **主要使用入口：**IDE 客户端。
- **工具权限：**删除类操作需要自己确认。

## 二、真实任务回顾

- **最近一次任务与完成标准：**算子开发；功能没有错误，性能达到要求。
- **不同 AI 的分工：**较弱的模型用于对话，Coding 使用较好的模型。
- **多 Agent 协作：**开多个对话。
- **任务时间分配：**图中只有问题，未记录回答。
- **多任务管理：**使用默认方式；一个对象正在修改时，另一个就没办法操作。
- **查找多轮对话中的有效信息：**不太好找，没有搜索功能。曾让 Agent 跑过一版数据；之后想找，只能手动往上翻。
- **任务过程：**先把需求描述、功能和目标给 Agent，让它设计方案并形成文档；用户检查并纠正错误、选一个最优方向，然后让 Agent 开发。
- **可回看的材料：**图中只有问题，未记录回答。

## 三、AI 如何参与任务

- **AI 帮助的步骤：**各步骤都有参与；选方案时人的参与较多。
- **没有 AI 时的做法：**人工完成。
- **访问官方文档、社区或 Sample 的时机：**给 AI 提供示例，一般在任务过程中用于纠错。
- **AI 找到官方知识来源仍无法解决问题的原因：**模型能力不够。

## 四、人何时介入

- **AI 卡住或反复报错的情况：**语料比较少。
- **接手方式：**先换模型，再给新的线索，例如之前的测试结果。
- **依赖经验的判断：**常见 API 的使用方式。
- **昇腾等专有技术场景的缺口与 Skill：**需要昇腾架构知识；性能优化最好提供 Skill。官方已有一些 Skill，但强约束较多、比较耗 Token，例如强制完成若干步骤，其中有些不必要。算子开发时会强制开多个子进程跑同一份数据集，要求所有结果都通过才合格；受访者认为跑一次即可。
- **一次关键转折：**思考过程中用了错误的环境，之后补充了信息。
- **改变问法、模型、工具或资料：**补充资料、制定方案。
- **答案参考来源：**希望看到来源，以确认真实性。早期很多答案是编的；希望在结果后附上参考来源。
