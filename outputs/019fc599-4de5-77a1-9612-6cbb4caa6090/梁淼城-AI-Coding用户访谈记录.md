## 一、用户基本信息

- **AI Coding 使用时长与频率：**约一年至一年半，每天都用。
- **过去三个月使用的工具：**Codex、Claude Code。
- **主要使用入口：**客户端、CLI。
- **工具权限：**“approve for me”；运行敏感命令需要确认，文件修改都让 Agent 自己做。

## 二、真实任务回顾

- **最近一次任务：**后端 Demo，修改开源仓库。
- **多 Agent / 多平台协作：**从 0 开始做；较好的模型负责设计，能力差一点的模型负责执行。多平台协作交接不好。
- **不同 AI 的分工：**根据模型能力；审美工作交给 DeepSeek。
- **Top 3 痛点：**过度设计（Codex 最严重）；跑偏、走岔路；第三项图中未记录。
- **任务时间分配：**提出目标与补充上下文、AI 执行、人工审查、经验沉淀约为 5:3:1:1。
- **多任务管理：**代码任务和个人任务并行；另开一个定时任务管理其他正在执行的任务，检查是否忘记回复。
- **查找多轮对话中的有效信息：**翻聊天记录，但加载很慢。
- **任务过程：**让 AI 解释开源库并寻找开源库、估算代码量，选择合适的技术路线、画架构图、写文档；确认后建项目骨架（空文件），每做一个模块就检查一次，主要看接口。
- **可回看的材料：**图中只有问题，未记录回答。

## 三、AI 如何参与任务

- **AI 帮助的步骤：**没有 AI 时会自己到各网站搜索，例如 GitHub、爱思唯尔；现在基本全过程都有 AI 参与。
- **AI 找到官方知识来源仍无法解决问题：**回答为“没有”。
- **相关 Skill / MCP：**操作浏览器；把 RAG 接进个人 Agent 时使用 MCP；Codex 使用 image_gen、Edge、Chrome 等，主要用于执行。
- **昇腾专有场景缺少什么：**错误样例。之前有一台昇腾服务器，排查错误很难；CANN 版本没有升级，所以跑不动。Codex 没有解决，也没检索到有效信息，最后手动用浏览器搜索。
- **昇腾官方 Skill：**CannBot；算子生成可生成接近 baseline 的结果。
- **访问官方文档、社区或 Sample 的时机：**新模型或新技术发布时，例如公众号看到上新时。
