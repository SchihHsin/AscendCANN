# 彭椒｜AI Coding 用户访谈记录

> 整理口径：思维导图手记为主，访谈 ASR 逐字稿用于补充细节。手记内容优先；逐字稿专名仅在语境或公开资料能交叉确认时规范，录音时间以方括号标记。手记中的“未记录”仅指截图未记回答；逐字稿若有清楚回答，会另列补充。无法确认的名称保留不确定性。受访者对工具和产品的描述仍是个人经历，不代表独立核验。访谈日期、访谈者未记录。

## 访谈主题

围绕近期真实经历回顾人与 Agent、资料与环境之间的协作；不要求受访者现场执行任务。

## 一、用户基本信息

- **AI Coding 使用时长与频率：**2023 年开始用，每天使用。
- **过去三个月使用的工具：**OpenCode、TestAgent、毕方。
- **主要使用入口：**CLI 客户端、网页对话。
- **工具权限：**基本全开。

## 二、真实任务回顾

- **最近一次任务与目标：**修测试脚本，让它跑通并通过（pass）；提到 CCE 编译器。
- **多 Agent 协作：**不涉及多 Agent 协同。
- **任务流程：**毕方可以对接服务器；把目标给它后，它会自动修正。
- **任务安排与管理：**时间主要花在提出目标和补充上下文；多任务并行。毕方界面拥挤，找不到当前任务。
- **Top 3 痛点：**生成速度慢、容易挂；内部业务信息不好获取；耗费 Token 多。对话历史不好找；OpenCode 中觉得有用的内容会手动保存在别的地方（VS Code）。

## 三、AI 如何参与任务

- **AI 帮助的步骤：**根据测试方案生成测试用例。以前需要逐条校准；AI 基本能覆盖，同质化场景交给 AI 没问题。
- **可信知识来源：**不一定完全可信。能找到类似资料，但找不到内部资料；依赖自己之前的经验时容易出问题。
- **相关 Skill：**团队内部 Skill 基本满足使用；业务需求迭代时也要更新 Skill，内部资源有限。

## 四、人何时介入

- **AI 卡住或反复报错时的判断：**人多时，日常习惯和记忆会帮忙记住。
- **接手后如何继续：**看到输出感觉业务结果不对，就改提示词；如果停摆，就换工具。
