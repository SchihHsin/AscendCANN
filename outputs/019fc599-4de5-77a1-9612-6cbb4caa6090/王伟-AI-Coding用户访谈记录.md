## 访谈主题

围绕近期真实经历回顾人与 Agent、资料与环境之间的协作；不要求受访者现场执行任务。

## 一、用户基本信息

- **AI Coding 使用时长与频率：**5 个月，每天使用。
- **过去三个月使用的工具：**Cursor、Grok；Trae 用于处理问题单和 Issue。
- **主要使用入口：**IDE。
- **工具权限：**全部权限。

## 二、真实任务回顾

- **最近一次任务：**算子开发，从 0 开发（图中文字写作“O开发”）。
- **不同模型的分工：**国外模型用于复杂任务，Trae 用于简单任务。
- **Top 3 痛点：**价格；语言表达“不说人话”；Trae IDE 不好用、比较卡、流畅度不够（图中括注 “solo”）。
- **多 Agent 协作：**一个平台开发一个项目。
- **任务时间分配：**提出目标与上下文会写得非常详细，约 1–2 天、15%；AI 执行约 1 天、10%；AI 执行与人工审查约 70%，两者相互交替；经验沉淀随任务结束。（图中比例和时长按原记录保留。）
- **多任务管理：**2–3 个任务并行。
- **查找多轮对话中的有效信息：**靠翻滚动进度条，不太方便，也没那么快。
- **任务过程：**把文档给 AI，AI 给开发者代码；用户大致看代码，发现问题后引用到对话里，告诉 Cursor 怎么改。
- **可回看的材料：**图中只有问题，未记录回答。

## 三、AI 如何参与任务

- **AI 帮助的步骤：**选方案和优化；个人做得比较多，人引导、AI 执行。受访者认为让 AI 优化时自己弄不明白，会白耗 Token。
- **AI 找不到官方知识来源的情况：**很常见；写文档时会把链接提供给 AI。
- **AI 找到官方知识来源仍无法解决问题：**常见。要实现较大的功能时，会给它 API 文档，因为多个 API 之间需要配合。
- **相关 Skill / MCP：**使用 CannBot 和自己沉淀的 Skill（用于方案设计文档）；图中记录“基本上都能有效执行、精度”，后半句未完整。
- **昇腾专有场景缺少什么：**回答为“基本上都能找到”。
- **昇腾官方 Skill：**流程很长、一步一步，任务还没开始 Token 就耗掉很多；一般不用工作流，主要用其中的知识。
- **访问官方文档、社区或 Sample 的时机：**开始写文档时先找会用到的资料；遇到问题且 AI 解决不了时自己找。会把官方解决思路（如 vector function）提供给 AI。

## 四、人何时介入

- **AI 卡住的情况：**精度调不通、像“左右脑互搏”；长时间完成不了时，会展开查看思考详情和已做的尝试。
- **接手方式：**给新线索或方案，例如找到官方解决思路、vector function，再把官方资料提供给 AI。
- **AI 失败后如何继续：**自己看 AI 代码很痛苦；受访者认为 AI 常做无效封装、定义许多变量再层层传递。完成功能后，会在保证功能的前提下清理代码、优化结构，自己查看后再告诉 AI 如何修改。图中另记：“AI 写出来的代码可读性比较差，commiter 让 AI 去看代码。”
- **不同经验水平的差异：**新手可能以“许愿式编程”完成任务，但过程更波折；遇到 AI 无法解决的任务，可能要请教资深者，再把方向交给 AI。资深用户会自己看代码，并能给 AI 更好的方向。

## 逐字稿补充（ASR 校订）

以下补充手记未充分记录的流程与判断；时间为转写文件时间，按语义整理，不作为逐字引文。

- **设计文档与 API（01:41:02–01:45:45）：**AI 给出初版代码后，受访者会通读并引用具体代码段反馈问题。通常在详设文档中加入相关 API 链接，避免 AI 猜接口；但复杂功能涉及多个 API 的组合，单个 API 文档仍不足以说明如何完成整体任务。
- **改错与代码整理（01:52:12–01:55:20）：**精度长时间调不通或 AI 思路明显不对时，会查看其思考和尝试，停止当前任务并补充新线索、重新定方向。受访者还会在功能完成后清理多余封装和变量传递；这部分需要人工反复指出问题，可能额外花一天。
- **算子验收（01:59:15–02:07:14）：**功能与性能需通过测试标准。精度通过昇腾结果与 CPU golden 结果的最大 / 平均相对误差判断；性能先采集基线，再比较改动后的结果。实际工具输出是主要信任依据。
- **工具名称校订（02:03:47–02:04:12、02:22:57–02:23:49）：**ASR 听作“my studio”；结合其“查看算子指令流水”的描述，规范为 **MindStudio Insight**。专门采集算子性能的工具听作“MS / msop”，按语境很可能是 **msOpProf**；逐字稿不足以确认具体命令。[MindStudio Insight 官方指南](https://www.hiascend.com/document/detail/zh/mindstudio/82RC1/GUI_baseddevelopmenttool/msascendinsightug/Insight_userguide_0009.html)、[msOpProf 说明](https://asc.gitcode.com/guide/programming_guide/debug_and_tuning/performance_tuning.html)。
- **学习需求（02:19:26–02:27:39）：**遇到问题时先围绕问题找最相关知识；主动学习时更希望了解背景和来龙去脉。受访者认为 AI 擅长快速读代码、读日志，但回答里抽象词太多时不易理解，因此希望用可视化图解解释算子架构和指令流水。
